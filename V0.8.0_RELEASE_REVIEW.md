# Macrotech v0.8.0 — Employee Workflow Pilot

Baseline: v0.7.3 Windows Test Repair, copied to a separate version. No production changes, emails, OAuth flows or connected spreadsheet writes were performed during development.

## Start on Windows

This ZIP contains source, a compiled React/TypeScript dashboard, tests and an EXE builder. It is **not a prebuilt or signed Windows installer**.

1. Extract the complete ZIP to a short folder such as `C:\Macrotech_v080`.
2. Run `BUILD WINDOWS EXE.cmd`. Internet is required for build dependencies. Keep Windows Security enabled; if it detects a threat, stop and retain its details.
3. After all build tests pass, open `READY_TO_TEST\Macrotech Quotation Pilot Demo\Macrotech Quotation Pilot Demo.exe`. Keep the accompanying files together.
4. Settings → About should show **0.8.0-demo**.

Local data uses `%LOCALAPPDATA%\Macrotech\Quotation Pilot Review v0.8.0`. Earlier drafts are not migrated or deleted. Start with the included recognizable 2026 examples or a new quotation.

## Suggested walkthrough

Edit, click Save, try Ctrl+S, then reopen the application to check recovery. Leave the optional note empty and request a percentage discount only if needed. Submit once to assign a Q-Code. Switch to the simulated CEO, approve, review the employee's approved PDF, then record partial PO quantities. Approval does not imply customer acceptance.

Expand quotation history to delete an unassigned draft or archive an assigned quotation. Use Show archived quotations to restore it. Archive is list management, not cancellation of approval, PO or Tracker rows.

Open Send to Customer, attach a document, remove its original source file and reopen the composer to verify the managed copy. Email sending remains disabled.

## Optional connected setup — performed by the tester, not the build

Place the approved pilot installed-application OAuth client file in the version's local data folder as `credentials.json`; never distribute it in the source package or EXE. Appropriate test-account access and Google configuration are still needed.

In simulated CEO mode, open Settings → My Tracker and enable synchronization after confirming the existing Dummy test destination. Enabling does not immediately send queued writes. Submit, approve or use the retry on that page. A failure remains pending under the same request/Q-Code; do not create a duplicate quotation.

Employee imports are read-only. A personal test mirror requires separate CEO confirmation of the linked ID. It needs the verified MARK-UP template and ACTUAL / _PILOT_CONFIG dependencies, which may be hidden. The app will not create, clear or repair an incompatible workbook. Mirror failure does not undo a successful Dummy write. Live 2026 TR is blocked as a write destination.

## Checks still requiring Windows or connected test data

1. Clean Windows build/launch, WebView2, native attachment picker, Ctrl+S, scrolling, focus, PDF viewer, crash/reopen and antivirus scan. No Windows execution or interactive browser visual review was possible here.
2. Verify EXE distribution without Python/Node installed. A centrally built, signed installer with upgrade/rollback remains required for employees. Current dependency downloads are not a fully reproducible signed release pipeline.
3. One controlled Dummy submit/approve/retry/partial PO: confirm same rows, formulas including P, styles and selected/alternate suppliers. Full live-template visual parity still needs controlled read-only comparison.
4. Confirm an authorized employee mirror; test denied permissions, missing dependencies and disconnection after master success.
5. Exercise interrupted writes, uncertain acknowledgments, rollback and full prepared-row capacity using disposable connected data. Cross-computer Sheets writes are not made atomic by this local release.
6. Test role changes/navigation during autosave in the Windows webview. Compilation is not an interactive UI test.
7. Attachment malware scanning is not implemented; extension and size limits are selection restrictions only. No real emails were sent.

## Simulated and parked work

Local JSON, role switching, the approval queue and Q-Code allocator remain single-computer features. They are not production authentication or shared Firestore. Contacts/attachments survive app restarts, not loss of the computer. Cloud backup, shared file storage, multi-user synchronization and central allocation remain release work.

Small parking lot: CEO-only Subnet / Net Profit after verified financial mapping. Other parked work includes customer logos, images embedded in quotations and employee online presence. Production Gmail routing, cloud services and deployment require separate work and authorization.

These tests do not prove zero bugs or production readiness.
